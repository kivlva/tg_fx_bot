# Telegram: DNS и резервные маршруты

На ВМ включайте TELEGRAM_RESILIENT_DNS=1. TELEGRAM_FALLBACK_IPS — до четырёх публичных IPv4 через запятую; это резервные адреса, не список официально гарантированных Telegram IP. Для текущей ВМ проверен 149.154.167.220. Не используйте --add-host одновременно с этим механизмом.

Resolver получает IPv4 из системного DNS, Google DoH и Cloudflare DoH, удаляет дубликаты и проверяет кандидатов параллельно по HTTPS без bot token. При TLS-проверке сохраняется server_hostname api.telegram.org и включена проверка сертификата. Первичная проверка выполняется до первого запроса. После истечения DNS TTL (не более 60 секунд) обновление выполняется в фоне при следующем обращении к resolver; запросы продолжают использовать ранее проверенный маршрут. После сетевой ошибки проверка выполняется синхронно перед следующим запросом. При неуспешной фоновой проверке рабочий список сохраняется и проверка повторяется не ранее чем через 15 секунд. Последние рабочие маршруты повторно проверяются при временном отказе DNS. Действующее keepalive-соединение может сохраняться дольше срока кеша.

После TelegramNetworkError соединение закрывается и список обновляется на следующем запросе. Сама сессия не повторяет запрос: это предотвращает добавление неявных повторов sendMessage с неопределённым результатом. Повторы polling выполняет aiogram. Resolver не меняет маршруты ВМ, DNS ОС, YDB и Lockbox.

Для обновления на ВМ: sudo sh deploy/update_vm.sh. Скрипт сначала собирает новый образ и проверяет HTTPS к Telegram внутри него без токена, затем останавливает и переименовывает прежний контейнер и запускает новый без --add-host. Прежний контейнер остаётся остановленным для отката; команды отката выводятся после запуска. Успешная сетевая проверка не гарантирует запуск YDB и обработку сообщений: проверьте docker logs, /start, конвертацию и сохранение валют после перезапуска.

В диагностике логируются DNS-источник, IP и доступность маршрута; токен бота не используется в DNS/HTTPS-проверках. Полный отказ всех адресов этим механизмом не исправляется: тогда нужен исправный прокси или устранение сетевой проблемы.
